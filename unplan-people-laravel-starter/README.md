# UNPLAN People — Laravel + MySQL backend starter

This is an integration starter for the existing `index.html` frontend. The repository currently contains only static HTML, so there is no Laravel app to integrate into yet. This package contains files to copy into a newly created Laravel API project.

## Recommended architecture
- Keep the current static dashboard at the repository root.
- Create Laravel backend in `backend/` (or deploy it separately to a PHP host).
- MySQL stores employees, attendance, and leave requests.
- Use Laravel Sanctum for API authentication.
- Serve the frontend over HTTPS. Browser geolocation requires a secure context (localhost is okay for development).

## 1. Create the Laravel backend
On your computer with PHP, Composer, and Node installed:

```bash
composer create-project laravel/laravel backend
cd backend
php artisan install:api
```

If `install:api` reports Sanctum is already installed or asks to confirm, follow the prompt; run it only once successfully. Then copy this package's `backend-files/app`, `backend-files/database`, and `backend-files/routes/api.php` into the generated Laravel project, merging folders rather than overwriting unrelated files.

> Laravel version is not known yet. Use the Laravel version generated by your current Composer setup, then check the official docs if commands differ.

## 2. Configure MySQL
Create a database and a dedicated database user in your hosting panel. Set the following in `backend/.env` (never commit `.env`):

```env
APP_NAME="UNPLAN People API"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://api.example.com
FRONTEND_URL=https://your-frontend.example.com

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=your_database
DB_USERNAME=your_database_user
DB_PASSWORD=your_strong_password
```

Use your real hosting values. Do not put credentials into GitHub.

## 3. Enable CORS
Edit `backend/config/cors.php` (create it using `php artisan config:publish cors` if your Laravel version supports that command) so `paths` includes `api/*`, `allowed_methods` is `['*']`, `allowed_origins` contains your exact frontend origin, and `allowed_headers` is `['*']`. Do not use wildcard origins with credentialed cookies in production.

## 4. Install / configure Sanctum
Use the Laravel Sanctum setup appropriate to your installed Laravel version. The API routes below use `auth:sanctum`. Create a user via your application's existing registration/admin process, then create an `Employee` row linked to that user's `id`. Do not enable public admin registration.

## 5. Add the Employee relationship to User

Edit `backend/app/Models/User.php` and add this method inside the `User` class:

```php
public function employee(): \Illuminate\Database\Eloquent\Relations\HasOne
{
    return $this->hasOne(\App\Models\Employee::class);
}
```

Keep any existing methods and traits in `User.php`.

## 6. Migrate and run
```bash
php artisan migrate
php artisan serve
```

API base URL for local development: `http://127.0.0.1:8000/api`.

## API routes (authenticated)
- `GET /api/me`
- `GET /api/dashboard`
- `GET /api/attendance`
- `POST /api/attendance/check-in`
- `POST /api/attendance/check-out`
- `GET /api/leaves`
- `POST /api/leaves`

All endpoints except login require a Sanctum-authenticated user. This starter intentionally does not include a public login endpoint; use Laravel's chosen authentication flow and issue Sanctum tokens only after validating credentials.

## Frontend integration
Copy `frontend/unplan-api.js` into your site and set `UNPLAN_API_BASE` to the deployed API URL. The helper expects a bearer token created by your authenticated login flow. Never hardcode an API token in HTML or JavaScript. If the current frontend has no login screen, build the login flow before using these authenticated APIs.

Example:
```html
<script src="./unplan-api.js"></script>
<script>
  // Call only after your authentication flow has securely obtained a token.
  // UnplanAPI.setToken(token);
  // const dashboard = await UnplanAPI.getDashboard();
</script>
```

## GPS and privacy
- Check-in captures the device's current coordinates only after the user grants browser permission.
- This starter stores a single location point for check-in/check-out; it does NOT do continuous/background tracking.
- GPS coordinates can be inaccurate or spoofed. Add server-side geofence rules for a specific workplace if required.
- Tell employees what location data is collected, why, retention period, and who can access it. Obtain appropriate consent and limit access.

## Important production work still required
- Set up an administrator account and employee onboarding.
- Add role/permission policies so employees can only see their own records and authorized managers can view teams.
- Configure CORS, HTTPS, backups, logs, rate limits, and password reset.
- Test migrations on a staging database before production.
- The dashboard must be updated to use real API data; this package does not modify or push to GitHub automatically.
